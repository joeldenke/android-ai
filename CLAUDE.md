# Android AI — Claude Plugin Marketplace

This repository is a **Claude Code plugin marketplace** for expert-level Android development.
It provides agents, skills, and hooks that encode the best practices from Google, JetBrains,
and the Slack Compose rules into every interaction.

## Quick Start

### Claude Code
```bash
@android-architect "Design the data layer for offline-first sync"  # Architecture decisions
/new-feature UserProfile screen with MVVM                          # Scaffold a full feature
/gradle optimize                                                   # Build system
/adb logcat com.example.app                                        # Device debugging
/figma-verify https://www.figma.com/file/ABC123?node-id=42:100    # Design system
```

### GitHub Copilot
```bash
# In Copilot Chat — paste the skill content as a prompt or reference the rules file directly:
@workspace /new-feature UserProfile screen with MVVM
@workspace /code-review src/feature/home/
@workspace /architecture-audit
@workspace /write-tests HomeViewModel
```

### Cursor
```bash
# Rules auto-loaded from .cursor/rules/ — just chat naturally:
Add a new UserProfile feature following MVVM Clean Architecture
Review HomeScreen.kt for Compose correctness
Audit the project for architecture violations
```

### Codex CLI
```bash
codex "Scaffold a UserProfile feature with MVVM and Clean Architecture per AGENTS.md"
codex "Review HomeViewModel.kt for coroutine and architecture issues"
codex "Write unit tests for UserProfileViewModel using JUnit5 and Turbine"
```

> Full agent definitions in [agents/](agents/).

### Windsurf

## Agents

Invoke with `@agent-name` in Claude Code. Each agent is a specialist — delegate to the right one:

| Agent | Speciality |
|---|---|
| `@android-lead` | Complex multi-domain tasks — coordinates the full team |
| `@android-architect` | Architecture decisions, module design, layer boundaries, ADRs |
| `@kotlin-expert` | Kotlin idioms, language features, code quality |
| `@compose-expert` | Composables, state, recomposition, Slack Compose rules |
| `@coroutine-flow-expert` | Coroutines, Flow pipelines, concurrency, structured concurrency |
| `@testing-engineer` | Unit, integration, and Compose UI tests |

Full definitions: [agents/](agents/) — also read as `AGENTS.md` by Codex CLI.

## Structure

```
skills/<name>/SKILL.md        # ← source of truth: Agent Skills format (agentskills.io), optional references/
agents/                       # ← source of truth for sub-agents
hooks/hooks.json + scripts/   # ← executable Claude Code hooks (see hooks/README.md)
mcp/servers.json              # ← canonical MCP servers (Google Developer Knowledge, Firebase, gcloud…)
.claude-plugin/               # ← plugin.json + marketplace.json (validate: claude plugin validate .)
.claude/  agents -> ../agents, skills -> ../skills, settings.json
.agents/skills -> ../skills   # ← read by Codex, Gemini CLI, Cursor, Copilot
.cursor/rules/ .windsurf/rules/ .windsurfrules .github/copilot-instructions.md GEMINI.md
                              # ← generated by scripts/sync-rules.sh — do not edit
AGENTS.md                     # marketplace index + Codex instructions
scripts/
  install.sh                  # installer per tool, plus `mcp <tool>` and `google-skills` (--help)
  sync-rules.sh               # regenerates adapters; --check validates skills + drift (run in CI)
```

### Editing rules

- A skill is a folder: `skills/<name>/SKILL.md` with `name` (= folder name, kebab-case) and `description` (≤ 1024 chars, says *when* to use it). Long material goes in `skills/<name>/references/*.md` and is linked from SKILL.md.
- Never add flat `skills/*.md` files. No agent discovers them.
- After any skill change, run `bash scripts/sync-rules.sh` and commit the generated files. CI fails on drift.
- Versions in skills must be verified (Maven Central, Google Maven, release notes). Never guess.

## Coding Standards (enforced everywhere)

- **Language**: Kotlin only — no Java in new code
- **Min SDK**: 26+ (use modern APIs freely)
- **Architecture**: MVVM + Clean Architecture (UI / Domain / Data layers)
- **DI**: Framework-agnostic — works with Hilt, Koin, Anvil, Metro, Dagger, or manual injection; patterns use constructor injection and interfaces throughout
- **Async**: Kotlin Coroutines + Flow (no RxJava, no callbacks)
- **UI**: Jetpack Compose — design-system-agnostic token model (Material3 optional, not required)
- **Design tokens**: `@Immutable` data classes + `CompositionLocal` — components never read raw values
- **Testing**: JUnit Jupiter (5/6) + Turbine + MockK + Compose UI test
- **Lint**: ktlint + Detekt + Slack Compose rules (zero warnings policy)
- **Build**: AGP 9 (built-in Kotlin) + Gradle 9 + Kotlin DSL + Version Catalogs (`libs.versions.toml`) + convention plugins in `build-logic/` + configuration cache
- **CI**: `gradle/actions/setup-gradle` with SHA-pinned actions; config cache encryption
